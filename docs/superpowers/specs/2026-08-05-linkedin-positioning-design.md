# Diseño de posicionamiento de LinkedIn

Fecha: 2026-08-05

## Objetivo

Reposicionar el perfil de Kevin Ríos Ferrer para búsquedas de Site Reliability Engineer, DevOps Engineer y Platform Engineer en México, Estados Unidos y posiciones remotas, manteniendo Cloud Architecture como ruta de crecimiento.

## Identidad profesional principal

- Título formal actual: Principal Application Software Engineer (IC4) en Oracle.
- Función principal: Site Reliability Engineering e infraestructura para telecomunicaciones 5G.
- Posicionamiento recomendado: Principal SRE con operaciones aumentadas por IA.
- La IA se presentará como multiplicador de capacidad operativa, no como una especialidad o título de AI Engineer.

## Evidencia verificable

- Administración de 29 clústeres destinados exclusivamente a desarrollo y pruebas:
  - 20 clústeres virtuales sobre OpenStack.
  - 5 clústeres bare metal.
  - 2 clústeres OKE en Oracle Cloud Infrastructure.
  - 2 clústeres Red Hat OpenShift.
- Soporte para regression testing, performance testing, functional testing, manual testing y procesos de desarrollo.
- Mantenimientos durante fines de semana.
- Incident response cuando los eventos corresponden a su zona horaria.
- Root cause analysis cotidiano para apoyar a equipos de desarrollo y testing.
- Automatización de RCA para identificar fallos en clústeres.
- Automatización de la configuración de clústeres nuevos para pruebas locales.
- Experiencia de liderazgo directo sobre dos personas durante dos años.
- Ownership individual posterior sobre la operación de infraestructura.
- Creación de procesos autónomos asistidos por IA para debugging, desarrollo, preparación de proyectos y merge requests, y generación de dashboards en Grafana y HTML.
- Impulso de la adopción de K8sGPT y Codex dentro del equipo.
- Inglés C1.

## Límites de precisión

- No afirmar responsabilidad sobre sistemas productivos.
- No inventar disponibilidad, SLO, MTTR, MTTD ni métricas de incidentes, ya que los ambientes son dev/test y no se miden formalmente.
- No presentar Ansible como dominio avanzado: puede leer, comprender y depurar playbooks básicos, pero no ha desarrollado manualmente un playbook completo.
- No presentar experiencia práctica con Terraform, Argo CD, GCP o Azure.
- No atribuir el título de AI Engineer, MLOps Engineer o Cloud Architect.
- No mencionar despidos; describir únicamente la consolidación del ownership y la automatización resultante.
- La reducción aproximada de 10% en AWS puede usarse como logro histórico, explicando que provino de limpieza de recursos antiguos, corrección de configuraciones sobredimensionadas y migración de VMs a contenedores. No inventar una línea base monetaria.

## Arquitectura del mensaje

1. Titular: nivel IC4 + función SRE + Kubernetes/observabilidad + operaciones aumentadas por IA.
2. About: identidad, escala, problemas resueltos, automatización, liderazgo y ruta de crecimiento.
3. Experiencia Oracle: separar responsabilidades operativas, escala, automatización y liderazgo.
4. Experiencia previa: destacar automatización mediante Bash, Python y Expect, instalación/configuración del producto y código de pruebas.
5. Aula MEJOR: conservar la reducción aproximada de 10% en AWS con explicación verificable.
6. Destacados: usar exclusivamente proyectos personales para demostrar observabilidad, automatización e IA privada.

## Titular base aprobado

Principal Application Software Engineer (IC4) | Site Reliability Engineering | Kubernetes, Observability & AI-Augmented Operations

## Criterios de éxito

- Un reclutador debe identificar en menos de diez segundos el nivel, la función y el núcleo técnico.
- El perfil debe comunicar alcance y ownership sin aparentar experiencia productiva inexistente.
- SRE, DevOps y Platform deben quedar como destinos inmediatos coherentes.
- Cloud Architecture debe aparecer como evolución profesional, no como cargo actual.
- Cada afirmación debe poder respaldarse con la experiencia descrita por Kevin.
