# Evidence Projects

Use an evidence project when proof artifact value is stronger than another badge.

## Project suitability

A project is suitable only when it can prove a repeated target requirement without inventing candidate experience. It must identify the target requirement ID, candidate fact ID(s), artifact owner, public-disclosure status, confidentiality risk, candidate isolation, and review gate before publication.

Good evidence projects:

- reproduce a target workflow in a safe synthetic environment;
- show code, architecture, dashboards, runbooks, writeups, or demo artifacts the candidate owns as a candidate-owned evidence project;
- disclose scope honestly as lab, personal project, or sanitized work sample;
- avoid customer data, secrets, private hosts, private repositories, and employer-owned material without documented rights-holder permission.

Weak evidence projects:

- copy a tutorial with no candidate decisions;
- imply production ownership that was not supplied;
- disclose private or customer material;
- take longer than the likely hiring signal is worth.

## Compare against learning

For every high-cost or expensive certification/course, compare at least one portfolio/project alternative when the gap can be proven by work. State why the project is higher, equal, or lower expected signal than the paid option. Keep `current_cost`, `duration`, `opportunity_cost`, `decision_basis`, and `next_action_gate` explicit. Project rows use `decision_basis` with `candidate-owned evidence`; project `next_action_gate` must say `publication requires exact authorization` plus the required ownership, secrets, confidentiality, and public-disclosure review.

Publication, upload, sharing, or portfolio deployment requires exact action-and-target authorization immediately before execution.
